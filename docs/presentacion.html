Snapshots: la factura nunca cambia

En detalle_ventas se copian el nombre y el precio del producto; en ventas, el nombre, RIF y dirección del cliente. Si mañana sube el precio, la factura de ayer conserva el valor original.

Una sola fila de configuración

Un índice único sobre una constante (((true))) impide que exista una segunda fila con datos fiscales contradictorios.

Consecutivos sin huecos

Las secuencias viven en esa fila única. La función las bloquea con FOR UPDATE, así que dos cajas nunca pueden sacar el mismo número.

Integridad: no se borra lo que ya se vendió

detalle_ventas usa ON DELETE RESTRICT. Si intentas borrar un producto con ventas, PostgreSQL responde 23503 y la app ofrece desactivarlo.

Seguridad

Tres barreras: RLS, funciones y triggers

Ocultar un enlace en el menú no protege nada: la última barrera está en la base de datos.

1

Row Level Security

Todas las tablas tienen RLS activo. Cada consulta se filtra por auth.uid().

  • El cajero solo ve sus ventas
  • El administrador ve todas
  • Ventas y detalle no tienen política de escritura: solo escriben las funciones
2

es_admin()

Función SECURITY DEFINER que responde: ¿el usuario actual es administrador activo?

  • Evita la recursión infinita del RLS
  • Se ejecuta con permisos del dueño
  • Se usa dentro de las políticas
3

proteger_rol()

Trigger que impide que un cajero cambie su rol o su estado.

  • Compara OLD y NEW
  • Si no es admin, lanza excepción
  • Desde el SQL Editor no bloquea (auth.uid() es NULL)
Ejemplo real: un cajero que escriba a mano /dashboard/usuarios es redirigido en el servidor; y aunque intentara llamar la API directamente, el RLS le devuelve solo su propia información.

El código

registrar_venta(): el corazón del sistema

Una función PL/pgSQL que o hace todo, o no hace nada.

-- 003_modulo3.sql create or replace function public.registrar_venta( p_cliente_id uuid, p_metodo_pago text, p_items jsonb, ... ) returns uuid language plpgsql security definer set search_path = public as $$ begin -- 1) Bloquea la configuración (secuencias seguras) select * into v_cfg from configuracion_negocio limit 1 for update; -- 2) Cabecera con números consecutivos insert into ventas (numero_factura, numero_control, ...) values ('FAC-' || lpad(v_cfg.secuencia_factura::text, 6, '0'), '00-' || lpad(v_cfg.secuencia_control::text, 6, '0'), ...); -- 3) Por ítem: bloquea, valida y descuenta for v_item in select * from jsonb_array_elements(p_items) loop select * into v_prod from productos where id = (v_item->>'producto_id')::uuid and activo for update; if v_prod.stock < v_cant then raise exception 'Stock insuficiente para %', v_prod.nombre; end if; update productos set stock = stock - v_cant ...; insert into detalle_ventas (... nombre, precio ...); end loop; -- 4) IVA y totales: aquí, no en el navegador v_iva := round(v_gravado * v_cfg.porcentaje_iva / 100, 2); update ventas set subtotal = v_gravado, monto_iva = v_iva, total = v_gravado + v_exento + v_iva; return v_venta_id; end; $$;

FOR UPDATE

Bloquea la fila mientras dura la transacción. La segunda caja espera y recibe el número siguiente, en vez de repetir el mismo.

SECURITY DEFINER

La función corre con permisos del dueño, así puede escribir en tablas que el usuario no puede tocar directamente. Solo ella y anular_venta() escriben en ventas.

Precio desde la base

El navegador envía cantidades; el precio se lee del producto. Un usuario no puede “cambiar” el precio desde la consola.

Redondeo a 2 decimales

Cada línea se redondea y el IVA se calcula sobre la base imponible. La pantalla usa la misma regla (lib/calculos.ts) para no mostrar diferencias.

Server Components por defecto

Las listas, el detalle y los reportes se leen en el servidor. Solo el carrito, los formularios, los gráficos y el PDF son componentes cliente.

Un esquema Zod, dos usos

El mismo esquema valida el formulario en el navegador y los datos en la Server Action. Una sola definición, dos barreras.

La lógica no vive en el componente

Los cálculos están en lib/calculos.ts, el formato en lib/formato.ts y la validación en lib/validaciones/. Fácil de explicar y de probar.

Zona horaria fija

Vercel corre en UTC. Todo se formatea con America/Caracas para que «ventas de hoy» no salga corrido 4 horas.
